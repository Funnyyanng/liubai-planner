## 性能样本

开发机上，排程引擎的 14 天、300 个任务测试场景，单次完整计算约 **150 毫秒**（Rust debug 构建，单次测量）。该测试设置了 3 秒上限并通过。

这不是最坏情况保证，也不包括界面、数据库、协调流程与 AI 等待。复杂依赖、窗口碎片和约束组合仍需持续收集基准；局部重排尚未单独形成统计性能报告。

## 桌面实际操作

使用独立测试数据库启动原生应用，验证了载入体验数据、生成计划、未完成反馈、更新剩余时间和查看延期因果链。最终 release 应用再次验证了启动、生成 6 个体验任务的计划，以及模块中心显示 AI 未配置时本地模块仍就绪。

## 第一版边界

- 排程是确定性启发式；当前找不到安排时公开缺口，不保证找到所有理论上可行的解。
- 高风险冲突保留原计划并要求用户修改任务、锁定安排或规则；尚无多方案并排比较与偏好学习。
- 模块基础具备生命周期、版本、事务、事件和边界检查；v1 为各模块独立 JSON 记录表，后续复杂查询可显式迁移至专有结构。
- 模块统一发布，未实现外部插件热安装。提醒依赖应用运行或恢复唤醒，不是独立常驻系统服务。
- AI 接口、结构校验及过期响应保护已实现；真实服务需用户配置 HTTPS 地址、模型和密钥后验证。未调用用户的付费 API。
- ICS 支持范围见 README。不支持的重复规则整批拒绝。
- 已构建 Apple Silicon 应用，尚未进行 Apple Developer 签名、公证或 Intel/Windows/Linux 验证。

## 复现

在项目目录按 README 执行构建、测试和格式检查。单独运行性能样本：

```sh
node scripts/rust.mjs test -p planner-scheduler benchmark_300_tasks -- --nocapture
```
